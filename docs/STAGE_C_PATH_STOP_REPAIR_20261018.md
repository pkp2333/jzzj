# C 阶段路径与停止确认修复（2026-10-18）

本次完成本地代码修复及离线验证，没有连接上位机、上传方案、部署代码、清除机器人 STOP_FAILED 锁存或发送机械臂动作。实物抓取尚未恢复验收：现场 `[89,-3,90,90,-1]°` 姿态仍无法通过当前抓取配置的路径预检。

## 改动与原因

1. **保持确认预算**：C 后端发送 0.25 秒保持轨迹时，显式设置 4 秒到位容差。以前只有驱动默认的 1 秒容差，无法在约 0.645 秒/帧的反馈下完成“参考帧 + 三次稳定比较”。C 总停止预算由 8 秒改为 12 秒，并同步客户端和任务适配器等待。启动检查要求总预算至少覆盖保持时长、到位容差、驱动内部停止和反馈余量。ABORTED、超时、缺失结果仍不能判定停稳。
2. **停止失败不再显示就绪**：服务器公开停止和持物锁存诊断，就绪检查遇到 true 或缺失值会阻止下一次抓取。后端保留原始停止失败原因，C 结果在必要时附带停止诊断。不会自动重启或消除锁存。
3. **开夹爪前做全路径预检**：以真实反馈为起点，只调用 FK/IK，预检接近、下降、抬升、运输整条路线。任何一步失败，先返回明确的失败原因，再走正常的停止确认；不会先打开夹爪才发现首段不可达。
4. **姿态逐步过渡**：平移和四元数同时插值。每个 IK 使用前一个预测关节解作为种子，保留原来的 0.35 rad 单步上限和硬关节限位。关节插值中间点以不大于 0.01 rad 的间隔核验 TCP 工作区和桌面间隙。执行前重新核对实际关节状态及实际起点的插值路径；计划期间反馈陈旧、取消或交权失效均会中止。
5. **显式关节过渡支持**：新增 profile 的 `transition_joint_waypoints_rad`（每点五个臂关节，弧度）及独立 `transition_calibrated`。默认空列表、false，不填未经验证的归位角度。配置过渡点后，必须经现场标定，并且整条后续抓取路线通过预检才会执行。夹爪角度始终保留实际回读。
6. **动态目标与运输路径**：目标在闭环对准后重新检查下降、抬升、运输可达性；运输采用先上抬、再横移、再下降，避免斜穿桌面间隙。
7. **IK 数值边界**：对恰好在 0.35 rad 边界、由浮点减法产生的最多 `1e-12 rad` 误差向内投影，再重新做 FK 残差验证。输出仍严格不超过原来的连续性上限，没有扩大限位或接受无效姿态。
