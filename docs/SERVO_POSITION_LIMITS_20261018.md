# 六路舵机统一原始位置范围

按用户要求，工程内六个舵机统一使用原始位置 `96..4000`（包含边界）。越界直接拒绝，不做饱和钳位。六路批量指令只要有一路不合法，整条指令在任何 I2C 写入之前拒绝，时间寄存器也不写。

`servo_protocol.py` 是换算与位置校验的共同实现。项目内 `CheckedArmDevice` 直接按已核对的 I2C 协议写单舵机寄存器 `0x19`、六路时间寄存器 `0x1e` 和六路位置寄存器 `0x1d`，避免原厂 SDK 先把角度钳成旧范围。沿用原 SDK 的标定基准、左右臂方向和字节顺序；位置量化为最近一个整数单位。单舵机、六路轨迹、旧测试入口和标定点动入口共用该边界。

`deploy/arm.yaml` 和示例配置改为 `servo_position_min: 96`、`servo_position_max: 4000`。移除驱动里重复的旧角度范围表；驱动根据六路统一位置范围及关节符号、零偏，生成运行时 `joint_lower_rad`、`joint_upper_rad` 供轨迹检查和规划器使用。各关节换算后的角度范围不同，来自原有标定映射，不代表设置了不同的原始位置限位。

反馈也要求原始位置在相同区间内，`0` 不再换算成 `-165°` 并当成有效角度。缺失、坏包和通信异常均保留失败，不使旧样本刷新为有效反馈。

本次没有改变 URDF 的运动学限位、TCP、相机外参或抓取方向，也没有发送真实运动命令。驱动接受某个原始位置，不代表该姿态通过了抓取全路径预检。当前第 5 舵机连续原始反馈 `0` 仍需排查，扩大驱动位置范围不能修复缺失反馈。

本地回归：161 项 C 阶段测试，158 项通过、3 项缺外部资源跳过；13 项工程测试通过。新增回归验证全部六路的 96/4000 边界、95/4001 越界整批拒发、坏参数零写入、105° 不再被钳成 90°、原始反馈 0 被拒绝、左右臂换算往返，以及单舵机和批量路径一致性。旧边界回放暴露原有钳位和零反馈问题。安装规则包含新的协议模块。

本地证据在 `.local/servo-position-before.log`、`.local/servo-position-core.log`、`.local/servo-position-project.log`、`.local/servo-position-validation.json`。方案文档留在本地，部署只传代码差异；现场构建及只读反馈结果另行记录。
