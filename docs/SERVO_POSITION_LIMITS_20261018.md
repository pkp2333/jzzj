# 六路舵机统一原始位置范围

按用户最新要求，工程内六个舵机统一使用原始位置 `96..4000`（包含边界）。每个舵机独立过滤，越界只跳过该舵机，不做饱和钳位，不给它发送替代位置或保持位置；其余合法舵机继续按原目标、原执行时间发送。全部超限则没有位置写入。此规则取代此前的整批拒发规则。

`servo_protocol.py` 是换算与位置校验的共同实现。项目内 `CheckedArmDevice` 避免原厂 SDK 先把角度钳成旧范围。六路全部合法时，继续使用同步批量寄存器 `0x1e`、`0x1d`；存在超限项时，只给合法编号发送单舵机寄存器 `0x19`，不向超限编号发送指令。沿用原 SDK 的标定基准、左右臂方向和字节顺序；位置量化为最近一个整数单位。单舵机、六路轨迹、旧测试入口和标定点动入口共用该边界。指令长度或执行时间等整体字段错误时仍拒绝整条指令。

SDK 返回 `CommandResult(sent_ids, skipped_ids)` 并记录日志。轨迹驱动允许有限数值的超限目标进入逐舵机过滤，等待实际发送的关节到位和测得停稳后，返回“部分执行”及跳过编号；不会因一个目标超限立即打断其他关节，也不会宣称整条轨迹成功。取消、通信故障和停止失败的处理保留。后续 C 阶段仍要求完整成功证据，部分执行不能推进 D 阶段。

`deploy/arm.yaml` 和示例配置改为 `servo_position_min: 96`、`servo_position_max: 4000`。移除驱动里重复的旧角度范围表；驱动根据六路统一位置范围及关节符号、零偏，生成运行时 `joint_lower_rad`、`joint_upper_rad` 供轨迹检查和规划器使用。各关节换算后的角度范围不同，来自原有标定映射，不代表设置了不同的原始位置限位。

反馈也要求原始位置在相同区间内，`0` 不再换算成 `-165°` 并当成有效角度。缺失、坏包和通信异常均保留失败，不使旧样本刷新为有效反馈。

本次没有改变 URDF 的运动学限位、TCP、相机外参或抓取方向，也没有发送真实运动命令。驱动接受某个原始位置，不代表该姿态通过了抓取全路径预检。当前第 5 舵机连续原始反馈 `0` 仍需排查，扩大驱动位置范围不能修复缺失反馈。

本地回归：165 项 C 阶段测试，162 项通过、3 项缺外部资源跳过；13 项工程测试通过。回归验证全部六路的 96/4000 边界、95/4001 逐舵机跳过、全部超限零位置写入、多条超限的编号与时间准确、整体坏参数零写入、105° 不再被钳成 90°、原始反馈 0 被拒绝、左右臂换算往返，以及单舵机和批量路径一致性。驱动回归直接使用实际收敛判断，确认其他五个关节到位后才报告部分执行，超限关节没有收到替代目标。安装规则包含协议模块。

本地证据在 `.local/servo-partial-before.log`、`.local/servo-partial-core.log`、`.local/servo-partial-project.log`。方案文档留在本地，部署只传代码差异；现场构建及只读反馈结果另行记录。
