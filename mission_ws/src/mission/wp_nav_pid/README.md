# 航点导航定位失效处理

2026-10-18 修复定位成功后再次丢失时不发停车命令的问题。

- `wp_nav/pose_timeout`：默认 `0.5` 秒，必须为有限正数。
- 两路输入为 `front_car_pose_orig_map`、`back_car_pose_filt_map`；必须携带新的有效采集时间戳。检测 Bool 的 true 不代替新位姿，false 立即使对应源失效。
- 首选源失效而另一源仍新鲜时使用另一源；两路均失效，在下一控制周期发全零 `cmd_vel` 和 `CarCmd.HOLD`，并持续发送。控制周期默认 `0.05` 秒，静默断流还受位姿超时约束。
- 同时检查 ROS 源时间年龄与单调时钟接收年龄，重复、乱序和过期位姿不能维持导航。失位/恢复清理 PID 和到位计数；恢复后允许继续原目标，退出也发送停车。
- 上游 AprilTag 现在只处理新鲜图像并保留采集时间戳；USB 相机停止给缓存旧图刷新时间戳。

离线测试与目标机验收步骤见[本轮修改说明](../../../../docs/REQUESTED_CHANGES_2026-10-18.md)。该机制依赖导航/底盘 ROS 进程正常运行，不替代 MCU 通信看门狗。
